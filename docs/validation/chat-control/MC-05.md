# MC-05: 任意回数上限と退役・停止の区別

2026-11-17。起点は`4586d66`、作業ブランチは`docs/worker-coordination-plan`。[計画](../../superpowers/plans/2026-11-17-worker-coordination-evolution.md)のMC-05だけを実装する。MC-06以降・実モデル試験・実UI受入は含めない。

## 実装

- `Broker`が専用configの`executionLimits`と版2工程表の`run.execution_limits`を読み、有限値の小さい方を使用する。旧`mcp.wake.maxTurns`も有限の試験枠として維持する。未指定／nullは無制限。wakeは配送直前に現行の工程表設定を読み、起動後のplan登録でも上限を適用する。
- wake／修正とも送信前に既存DBへ予約する。同じoperationの再照合で重ねて送信・消費しない。結果不明は消費したまま停止し、再送しない。修正枠の枯渇はworktree割当前に判定する。DB migrationや依存追加はない。
- 親専用MCP`retire_worker {target}`と、既存のnative管理経路を使う拡張の対象退役・全体停止を追加した。native受付には`retire_worker`を追加し、モデル所有プロセスの非MCP制御禁止、token／owner／epoch／window lease／WorkerRef／terminal bindingの照合を維持する。
- 退役と全体停止は同じattemptの停止を共有し、停止中も人数に計上する。終了不明は全体を停止する。退役はタスク完了・依存解放・自動再割当ではなく、工程表の`retired`状態と旧成果を残す。保留中なら相談の再開条件も保持する。新担当への引継ぎは明示した`handoff_new`を必要とする。
- タブ削除／`stop_worker`は従来のrun配送・wake停止を維持する。退役・全体停止でログタブを閉じず、未コミット成果・ブランチ・worktreeを削除しない。終了済みタブの閉鎖は表示だけ。通常監視はモデルを呼ばない。

## 検証

既存テストとfixtureを拡張し、固定上限による失敗・未実装の退役経路をREDで確認した。主な回帰確認は次のとおり。

- 既定／nullで14回のwakeと初回＋4回の修正を実行できる。12を超える正整数も指定可能。
- wake=3／修正=2で上限を守り、予約済みの結果不明と重複operationを二重消費しない。親active中はsteerせず、配送不明・owner喪失・終了不明は既定無制限でも停止する。
- 版2工程表の有限枠とconfigの厳しい方を適用し、枯渇時に新worktreeや割当を残さない。
- 退役は親専用で、旧WorkerRefや二重停止が新attemptに届かない。全体停止との競合中も終了確認まで枠を保持し、遅延した正常完了で退役を完了扱いにしない。
- native Jobとhostの停止を実fixtureで確認し、対象退役後も独立ワーカーが稼働する。親モデルなしのCLI／拡張の全体停止、タブ閉鎖の従来動作、ログ・未コミットファイルの保全を確認する。
