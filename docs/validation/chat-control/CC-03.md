## 実装

- `src/wake.ts`とmigration 003: run単位にイベントを集約。走査位置、親の既読位置、配送済み位置、operation、停止世代、親identity、開始turn IDを別々に永続化する。通常監視は保存済みイベントの有限読取だけで、delta・描画・heartbeatではモデルを呼ばない。
- 正常完了のwakeは、保存済み報告とworkerの正常turn・未解決要求なし・後始末の確認後だけ。失敗・質問・人の承認待ちも候補とし、早いreportを完了へ変更しない。報告なしで正常終了した場合は失敗イベントを残す。
- 親relayの同じwriter gateでowner/epoch・状態seq・active/pending・未完UI入力を確認して枠を予約する。標準queue／steerの観測時は自動wakeを未対応にし、二重配送しない。同一入力chunkの未処理フレームも予約を維持する。
- wake用native入口は、専用control hostの直接の子であるbrokerについて、保持したprocess handle、作成identity、job、Node／入口hash、argvを検証する。外部の同一利用者プロセスや子モデルからwakeの再開・停止を代用できない。
- 停止時はbroker内の新規配送を禁止し、native送信箇所のfenceを確定してからDB停止世代と子停止へ進む。親接続失敗でも子停止を継続する。配送不明は保存・停止し、自動再送と単なる明示再開を拒否する。停止中の旧イベントは明示再開で再配送しない。
- 親再開最大12回、同一taskの修正は履歴選択に関係なく2回まで。上限で停止理由を保存する。再開指示はrun/event ID・固定文だけとし、子の本文は管理命令へ連結しない。
