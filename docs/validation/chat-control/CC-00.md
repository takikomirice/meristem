# CC-00 実施結果

実施日: 2026-11-15（日本時間）。対象は[実装計画のCC-00](../../superpowers/plans/2026-11-15-codex-chat-control-implementation.md)のみ。

**判定: `needs_redesign`。接続実証は成立したが、A経路の採用とCC-01への昇格は保留。** 通常UIの停止後にターンが`interrupted`になっても、既に開始したコマンドのマーカー追記が続いた。APIによるターン中断を、コマンド停止完了と扱うことはできない。

## 実装したもの

- `native/Program.cs`, `StdioRelay.cs`: exeの絶対パス・SHA-256確認、引数と通常通信の転送、管理RPCの分離、登録対象と実catalogによる制限。観測は8 MiBまで、イベントは本文を含まない直近256件。
- `native/LocalPipe.cs`: 現利用者とSYSTEMの保護ACL。Network SIDを拒否。同一利用者の非sandboxプロセス全体に対する防御や役割認証ではない。
- `native/ProcessTree.cs`: 子をsuspendedで作成し、kill-on-closeのJob Objectへ所属したことを確認してから実行。継承する標準入出力handleを限定。チャットの中断にはjob全体のkillを使わない。
- `scripts/build-native.ps1`、偽Codex exe、`node:test`による通信・終了・MCP・runnerのテスト。
- `relay-probe.mjs`: 明示的な実機runner。未認証transportと専用VS Code profileの準備・試験・設定復元。
- `caller-probe.mjs`: 公式MCP SDK `1.32.2`とzod `4.6.7`を固定。実要求metadataのキーとthread/turn IDのみ返す読取専用ツール。IDを引数で指定できず、役割認証や権限付与は行わない。

SQLite、broker、工程scheduler、変更系MCP、インストーラーは作成していない。既存Meristem、拡張本体、グローバルなCodex／VS Code設定は変更していない。

## A/B/C別の採否

| 経路 | 判定 |
|---|---|
| A: 拡張所有の同じ接続 | 接続、通常UI、別cwd、同じ子、親再開の入口は成立。ただし実コマンドの停止条件が不成立のため採用保留 |
| B: 外部所有で作成後、拡張へ移す | 未試験。今回のAの成功をBへ転用しない |

## 残る制約と判断

1. **停止を再設計する。** `turn/interrupt`の受付・`turn/completed(interrupted)`と、長時間shell sessionの終了を別々に扱う必要がある。共有App Serverのjob全体をkillすると無関係な会話も失われるため代用しない。候補は、元command/sessionと所有threadを相関し、対象を限定した正式な終了APIの有無を実版で調べること。`thread/backgroundTerminals/*`等の対象範囲・通常コマンドとの対応・権限制約は今回実証していない。これを次の小さな設計／接続試験として扱い、CC-01実装で隠さない。
2. **固定版のenvelope制約。** 8 MiB超と切断途中の管理応答の隔離は、実版で観測したID-first形式（先頭512 bytes以内）を前提とする。任意のJSONメンバー順序での隔離は保証しない。別版や形式変更時の常用は不可。通常の完全な8 MiB以内のフレームはJSONとして相関する。
3. **IDの完全衝突。** 通常の拡張bytesとIDは保持する。将来の拡張IDが送信済み管理IDと完全一致する例外だけは、一時IDへ変換して応答の元IDを復元する。元の同形ID・管理IDの分離は試験済みだが、この完全衝突分岐の専用試験は残っている。通常通信の全bytesを無条件に同一とする主張はしない。
4. **承認・秘密・Gitの境界。** 実試験は専用fixtureだけを対象にし、既存の通常チャットへ送信しなかった。観測した全threadの履歴を読む操作は、自動承認レビューが私的履歴取得の可能性を理由に拒否したため実行していない。その後は通常UIでPを再選択して送信イベントを対応付け、Pの特定IDだけを読み取った。認証情報・raw通信・全会話履歴を公開証拠へ保存していない。
5. **実施環境とスキル運用。** 計画時と異なりGit管理下だったため、既存のクリーンな作業場所で専用ブランチを使用した。WindowsのCC-xx工程に合わないBashのledger helperの代わりに、非公開の実行記録と本結果を使用した。GUIは試験のため可視起動し、親VS CodeのElectron Node-mode/IPC変数だけを新プロセスの環境から除いた。グローバル環境は変更していない。

これらの判断が誤っていた場合の影響は、停止漏れ、管理応答のUIへの流入、応答先の誤相関である。常用・後工程への昇格は行わない。別利用者拒否、実機の残項目、CC-01以降は未確認・未実装のまま残す。

## 検証・レビュー・再現

ビルド・通常テストの手順は[README](../../../README.md)を参照。実行ポリシーを変更せず、許可された通常のPowerShellから指定のnativeビルドを実行した。

最初の通信テストは中継未実装で失敗を確認した。起動引数・policy overrideの境界も修正前の失敗を確認した。独立した読取専用レビューのImportant 2件（途中で切れた管理応答のUI流入、transport runnerの早期終了／timeout時の待機放置）は再現テストを失敗させてから修正した。設定復元で無関係な編集を消す懸念も修正し、回帰確認を追加した。最終のテスト数・結果・最終ビルドhashは[verification](CC-00.verification.json)に保存する。

コードレビューと自己レビューの合格は、失敗した実機停止条件を上書きしない。GUI実証は証拠の`uiTestedRelaySha256`の版で行い、その後のEOF／runner修正を含む最終版は別途ビルド・通常テスト・実Codex transportを確認する。最終版でGUI全項目を再受入したとは扱わない。
