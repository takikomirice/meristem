## 実装

- 版1は`workspace`へ正規化し、版2の`agent.permissionProfileId`を割当・runtimeへ渡す。未知profileはGitの割当前に拒否する。
- RunPermitのscope hashへ専用configの`permissionPermit`を含め、coordinator toolの引数で権限上限を変更できないようにする。省略時は従来のworkspace/userを使う。各担当のcwdを上限に照合し、明示的な書込みrootをそのcwdだけに絞り、管理領域との重複・alias・範囲外cwdを拒否する。
- 既存の実catalogのページング検査を再利用し、起動応答のmodel、reasoningEffort、reviewer、approvalPolicy、profileのid/extends、runtimeWorkspaceRootsを照合する。任意のconfig入力、guardian_subagent、Full Accessへのfallbackは追加しない。
- `Registration.settings`に要求agentと応答照合済みpermissions、引継ぎ方式・元thread参照を追加し、statusから確認できる。既存DBの移行や既存レコードの書換えは不要。旧レコードでの欠落は未確認のまま扱う。
- 対象版の生成schemaで永続化grantを確実にresetできるAPIは確認できなかった。計画で認められたfallbackとして、履歴継続の選択でも停止済み・未解決要求なし・clean Gitを照合し、同じworktreeを独立した新threadと新attemptへ引き継ぐ。旧会話・grantを再生せず、元thread参照、新しい指示、コミット済みファイルを使う。会話本文が自動で引き継がれる挙動ではない。
- 自動レビュー拒否後、同thread/turnの正式承認を親や人のacceptで上書きしない。実MCP承認schemaにはitemIdがなく、network reviewのtargetもnullになり得るため、同turnの正式承認は保守的に未対応として保持する。通常の質問は権限を追加せず回答できる。本人確認・connector等の未対応同意も保留を維持する。
