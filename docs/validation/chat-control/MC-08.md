# MC-08 人の合意に基づく工程表改訂

2026-11-18（日本時間）。[MC-08の実装計画](../../superpowers/plans/2026-11-17-worker-coordination-evolution.md#mc-08-人の合意に基づく工程表改訂)に従い、MC-07統合済みの `ed9401b` から専用worktreeで実装した。

## 承認と反映

- コーディネーターは既存タスクの依存関係・必須検証・担当設定を構造化して提案する。フォームに保存対象の変更前後、影響範囲、理由、代替案、推奨案を表示する。人のフォーム回答を、相談ID・旧版・提案・フォーム世代で照合する。
- `apply_plan_change` は承認済みの旧版と提案版の組だけを適用する。既存のRunPermit、Gitの割当範囲、タスクID、実行上限、統合済みの実績を保護する。運用中のMarkdown本文を保持し、進捗の投影には`write_progress`を使う。
- 依存関係から影響タスクを求め、対象の旧attemptは終了確認後に適用する。改訂前の成果と旧worktreeは参照できる。再開は新しいattemptとworktreeを使い、配送指示に改訂後の依存関係と必須検証を加える。独立したattemptは続行できる。
- 旧版の未完了フォームや未適用承認を失効させる。ブロッキング相談は終了操作の有無にかかわらず制限を保持し、現行版の相談で保留理由を置き換えられる。増員承認の回答は履歴に残し、新しい版では承認上限を照合し直す。
- Markdown置換後のDB保存に失敗した場合は配送を凍結する。保存済みの人の回答と厳密に一致する差分で再照合できる。従来DBで本文ハッシュがない場合は、そのDBが記録したファイルハッシュに一致する原本から照合する。

## 検証

旧実装に対し、未承認編集の照合拒否と新しい改訂経路の3テストが失敗することを確認した。初回の指定4ファイルは90件成功した。独立レビューで、物理的な終了操作前のブロッキング相談の失効と、旧DBの本文照合に重要な指摘が各1件あった。相談の制限維持、旧ファイルハッシュの使用、適用前の明示取消、フォーム表示の不可視文字エスケープを回帰テストに含めた。

レビュー後の`npm run build`と関連回帰9件が成功した。最終`npm run verify`は終了コード0で、ネイティブビルド、型検査、本体・拡張ビルド、通常42件、制御338件、端末15件の計395件が成功した。作業ブランチ`docs/worker-coordination-plan`へfast-forwardで取り込む。コミットSHAとプッシュ結果は完了報告に記録する。

実モデル、実VS Codeのフォーム、追加のOS隔離は `not_run`。承認フォームはMCP SDKのインメモリ接続、Gitの割当と成果照合は実ローカルbare remote、配送・終了確認は決定的fixtureで観測した。README日英、運用リファレンスと同梱の操作手順を更新した。
