# CC-01 実行記録・停止・再照合

実施日: 2026-11-15（日本時間）。対象は計画書のCC-01のみ。CC-02以降、通常profileへの導入、実モデルの追加送信は実施していない。

## 実装

- `src/store.ts`と`migrations/001-control.sql`: SQLiteの単一writer、schema拒否、操作ID/payload hash/revision、起動前の作業場所予約、イベント、停止世代。OSが解放するSQLite排他transactionでwriterを所有し、PIDファイルの削除で奪取しない。
- `src/broker.ts`: 記録後の指示配送、ACK喪失の再送禁止、既知拒否の分類、タブ閉鎖・run停止・lease喪失、正常完了の後始末。正常turn終了を報告や工程受入として捏造しない。
- `native/ControlProgram.cs`: ACL付き16接続、実peer PID/作成identity/所有job照合、Nodeへの専用stdio。worker配下の接続を人の停止CLIとして扱わない。Nodeに第二のpipe/HTTPサーバーを作らない。
- `src/workers.ts`とnative worker: pinned exe、owner/epoch/attempt、実root threadとcatalog、suspended起動、停止前のidentity照合、全job終了の確認。予期しないApp Server終了でも孫を終了させ、brokerへ不明状態を通知する。
- `extension/src/managed-client.ts`: 明示discovery、担当タブとwindow leaseの区別。既存CC-00R fixture接続と読取専用terminalを保持。
- `src/cli.ts`: `status`／`stop`と管理プロセス入口。オフライン時はDBを読むだけで、過去PIDへ操作しない。

## 検証

`npm run verify`はnative build、ルートと補助拡張の型検査・build、既存33件、CC-01のDB/broker/worker/native管理接続試験、terminal 12件を実行する。詳細な最終件数・結果・hashは`CC-01.evidence.json`を参照。

確認した経路:

- 重複操作・payload変更・revision競合・schema未知・二重writer・再起動時の`needs_reconcile`。
- 指示送信の同時競合、完了通知がACKより早い場合、認証・利用上限の既知拒否と配送不明の区別。
- 古いepoch/terminal bindingの拒否、所有workerから親制御口への接続拒否。
- 子タブ閉鎖時の兄弟継続、window lease切断・親UI停止での全子停止、別親threadからの停止を無視、停止後も親の通常通信が利用可能。
- broker/host/App Server終了、再起動後の再配送禁止、登録失敗の後始末、起動予約後の作業場所再利用拒否。
- 正常完了後のhost解放とrun継続、停止後のマーカー無増加、未コミットファイル保持。
- 実Codexの無推論sandboxで管理領域のread拒否、実root thread・`meristem-managed` profile・job停止の確認。認証payloadやraw通信は証拠へ保存していない。

## レビューで修正した点

独立レビューのImportant 4件（App Server異常終了時の孫残留、正常完了から後始末への接続不足、登録失敗時の未登録worker残留、既知拒否の分類不足）を修正し、回帰試験を追加した。加えて、native切断前の応答消失と同時sendの競合、起動途中の予約欠落を確認・修正した。指摘の再現試験と最終検証は成功し、既知の未解決Critical/Importantはない。

## 今回の判断と確認範囲

- 既存のfeature branch上で実装し、利用者の`debug.log`変更は除外した。worktree作成の形式的な承認待ちは挟まなかった。
- CC-01の`dispatch`は管理内部からのみ使う。実MCP metadataからの`CallContext`導出と公開変更ツールはCC-02で接続する。callerをツール引数で自己申告させる暫定APIは公開していない。
- 実モデル送信は0回。Windows nativeによるマーカー停止と再起動はMockCodexで検証した。新managed経路で実モデルが起動したshell/孫、実VS Code GUIでのmanagedコマンド操作は今回の証拠に含めない。旧CC-00Rの実モデル・GUI証拠を新経路の結果へコピーしない。
- 正式承認UI、親wake、Git統合、通常導入は後工程。未対応のserver requestには自動承認せず待機する。
- 再起動後の明示再開は公開していないため、照合前は停止したままとする。これは終了確認不能のworktreeを自動利用しないための制約。
