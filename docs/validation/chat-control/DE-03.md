## 実装

- `src/development.ts`: 環境とauthHomeの排他lease、CLI操作lock、runのphase／所有receipt／プロセスidentityを記録する `lifecycle.json`、起動・status・停止・復元APIを追加。不変のsession、snapshot、run別identity、予算を維持する。
- `test/live/development-session.ts` と `scripts/development-process.ps1`: 明示した専用Windows環境だけを起動し、既存installer／broker stop／DBのstop記録／OSの実体と作成時刻を照合する。通常ウィンドウ終了を要求し、保存確認等で終了しなければ `unknown`。Kill、PIDだけでの停止、sandbox setup、モデルturnの送信は追加しない。
- 既存 `cc02-prepare.ts`／`cc02-session.ts` は `--environment` 指定時だけ開発経路へ分岐。旧受入の `--window-closed`、有限送信枠、launch契約は維持する。旧runnerの一時auth書込みも同じlockに参加し、開発runとの競合を拒否する。
- installer本体の動作は変えず、既存のMCP namespace判定をexportして再利用する。元の `cc02-restore.ts` は旧受入用であり、変更しない。
- 日英READMEと[開発手順](../../development-environment.ja.md)を更新。新規依存はなし。

固定profileと正式authHomeは残し、新runはDB、run ID、pipe、親binding、設定、receiptを別に生成する。環境leaseとauthHome leaseは停止後も復元まで維持し、未知の状態を自動解放しない。利用者の設定変更、Git成果・未コミットファイル、snapshot、旧DB、証拠は削除しない。既存MCP entryがあれば導入前に拒否し、編集された所有MCP tableは保持して再利用を止める。
