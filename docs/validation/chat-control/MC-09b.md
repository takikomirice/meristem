# MC-09b 管理ターミナルの実接続

2026-11-18。MC-09a、MC-11a、MC-10aを順に統合した `0bf3d75` から、`feat/mc-09b-terminal-events` の専用worktreeで実装した。MC-11bも同じ起点を使用する。[工程表](../../superpowers/plans/2026-11-17-worker-coordination-evolution.md)

## 表示と停止

- 工程表版2の初期表示名と、管理ウィンドウからの表示名変更を同じattemptへ保存する。名称変更はウィンドウのリースと完全な`WorkerRef`を照合する。同名、日本語、ブランチ風の名前を使える。名称変更による実行版、ブランチ、配送、権限の更新は発生しない。
- 既存のWorkerHostが接続するApp Serverから、現在のthread・turnに一致するコマンド、ファイル編集、進捗説明の通知を分類する。ターミナルへ送るのは活動の種類、受信時刻、終了コードなどの限定情報。進捗説明は発生を表示する。コマンド本文、出力、編集差分、会話本文、内部思考は表示用データに含めない。
- 実行状態、タスクの保留・退役、相談状態を独立して表示する。保留の実行枠解放には既存の停止確認を使う。終了済みのattemptはID指定で引き続き照会でき、相談の追加・決定はrunの更新として保持されたタブに反映する。
- 表示用の活動はattemptごとに最新64件をメモリに保持する。状態イベントと活動イベントの取得位置をそれぞれ管理し、状態取得失敗時は進めない。未回答の相談を優先して最大16件・40,000 bytesを表示用に取り出し、省略を通知する。活動監視はモデル送信を必要としない。
- タブ一覧の定期取得と全体停止の応答は、相談の集計を行わない。実行中の管理タブの閉鎖は既存のゲートウェイへ直接依頼し、ゲートウェイがattemptと終了状態を照合する。ターミナルの非表示やクリアは停止操作に含めない。

## 検証

- 共通起点 `0bf3d75` の `npm run verify` は通常42件・制御346件・端末25件の計413件が成功。
- REDで実イベント、表示名、保留状態が未接続であることと、完了済みタブに相談結果が反映されないことを確認した。接続後はWindowsのnative gatewayとApp Server fixture、ローカルGitのMCP／Broker／Store、VS Code拡張の端末fixtureで確認した。
- 差分レビューで見つかったAuthorizationヘッダーの認証値残留は、backendと描画の両方でREDを再現して修正した。終了済みタブへの追加相談の反映と、一覧・全体停止・タブ閉鎖が表示用の集計や取得失敗に依存しないことを確認した。
- `npm run build:native`、`npm run build`、`npm run typecheck` が成功。通常42件、制御・ワーカー50件、DB 10件、端末29件が成功。DB回帰では128件のページングと、一覧から外れた完了済みattemptの照会を確認した。個別実行のnative検査では途中に表示接続の終了待ち1件がタイムアウトし、同じ実装に対する一式の再実行で10件が成功した。VSIX検査の単独実行も成功した。

実Codexモデル、実VS Code UI、通常環境への導入、追加OS隔離は `not_run`。操作と表示の利用案内は[運用リファレンス](../../chat-control-reference.ja.md#管理ターミナルの表示と操作)を参照。
