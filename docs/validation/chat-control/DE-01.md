## 実装と検証

`inspectEnvironment` はinstallerのパス・hash検証を再利用する読取り関数。通常設定・auth設定の全byteとディレクトリ構成を比較し、起動記録とsubprocess API呼出しが空であること、秘密文字列をレポートへ出さないことをfixtureで検証する。選定の維持、実体消失・hash不一致、1909／setup失敗／timeout、設定参照不一致、重複sandbox設定、終了状態不明を確認する。

- RED: 実装前のbuildは診断module不存在で失敗し、生成されたテストも `ERR_MODULE_NOT_FOUND` で失敗。重複 `[windows]`、複数行文字列・引用キー、既存relay設定の回帰テストも修正前の失敗を観測した。
- GREEN: `npm run build`、`node --test dist/test/development.test.js`（7件）、`npm run typecheck`、`npm run test:terminal`（14件）は成功。
- `npm run verify` はWindows PowerShellの実行ポリシーにより `scripts/build-native.ps1` 読込み前に失敗。native再ビルドは `not_run`。ポリシー変更・実行制限の迂回は行っていない。
- `npm test` は42件中39件成功、3件失敗。同じ実行ポリシーにより、`VSIX includes license and notices, excludes private state, and never overwrites an artifact`、`release ZIP runs with its own Node and locked dependencies and contains no developer state`、`release packaging rejects junction ancestors before reading inputs or creating output` が失敗した。
- `npm run test:control` は206件中195件成功、11件失敗。以下の既存テストは未通過として残す。DE-01の最終7件はその後の個別実行でも全件成功。実モデル／sandbox起動／UAC／実UI受入は今回 `not_run`。
- 独立した読取りレビューで、既存relayを直接Codexと誤比較する問題と、TOMLの複数行文字列・引用キーを設定と誤認する問題を確認。両方を回帰テストのRED→GREENで修正し、自己レビューで設定更新・権限緩和・自動再試行・停止操作への経路がないことを確認した。relayのsidecar一致はreceiptによる許可成功とせずwarningを残す。

判断: 計画のinterface例に、明示した選定hash・任意の設定参照・失敗事実を追加した。選定hashがなければ比較対象がなく、観測済み失敗を再実行せず報告するには入力が必要なため。既存の公開API・保存形式は変更しない。

制御系の失敗名と根拠:

- 実行ポリシーによる `scripts/install.ps1` 読込み拒否: `install_preserves_unrelated_settings`、`uninstall_preserves_new_user_value`、`profile_copy_and_absent_key_restore_preserve_later_user_settings`、`uninstall_retains_mcp_section_when_user_appends_a_key`、`uninstall_removes_inserted_key_comma_across_user_comment`、`install_preserves_unrelated_project_table_named_meristem`。
- 既存native fixtureがMC-02追加処理を含まない状態: `multiple_question_fixture_roundtrips_free_text_and_rejects_partial_or_stale_answers`、`compatibility_probe_checks_applied_settings_history_and_never_claims_UI_or_review_decisions`、`compatibility_probe_reserves_one_turn_and_preserves_rejection_without_retry`、`guardian_probe_records_two_bounded_assessments_without_executing_commands`、`guardian_probe_distinguishes_injection_failure_and_does_not_continue_after_rejection`。現在のMockCodex.exeは2026-11-16生成、fixtureソースはMC-02の2026-11-17 commitで更新されている。ソースにある `compatibility-fixture.json`、`thread/guardianReview`、`thread/inject_items` の文字列がexeのUTF-16文字列にないことも読取り確認した。今回native再生成は実行ポリシーで止まっており、MC-02受入成功としない。
