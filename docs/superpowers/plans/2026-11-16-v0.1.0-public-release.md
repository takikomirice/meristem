# Meristem v0.1.0 Public Release Plan

**Goal:** Publish the reviewed Windows implementation with one public root commit, a `v0.1.0` tag, verified release assets, and no personal account paths or private email addresses in the published tree or commit metadata.

**Architecture:** Keep the existing runtime and authorization contracts. Package the compiled application, helper VSIX, a verified Windows x64 Node.js runtime, and the locked npm packages with their original license files. Installation still requires the user's dedicated VS Code/Codex profile, official login, explicit plan/repository binding, and human authorization.

**Scope:** The user explicitly authorized squash integration into main, rebuilding main as one commit, tagging, release publication, deletion of all non-main work branches, and changing repository visibility to public. Local recovery data stays outside the published tree and release assets. No model calls are needed for this release.

## Steps

- [x] Inspect local changes, remote branches, tags, releases, pull requests, and repository visibility.
- [x] Save and verify a local Git bundle and the working README change; configure only this repository to use the verified account's GitHub noreply address.
- [x] Add a versioned release packager, installation guides, and release notes. Set package metadata to `0.1.0` and preserve the existing README wording change.
- [x] Check package failure cases and actual ZIP/VSIX contents, dependency versions/licenses, bundled Node provenance, and extracted-runtime startup and fresh database initialization without model calls.
- [ ] Run the mandatory verification suite on the integrated tree. Independent read-only review is complete; SQL inclusion, ancestor-junction rejection, and recursive-input output rejection were fixed and regression-tested.
- [ ] Squash the work branch into main and verify the resulting tree. Rebuild main as a parentless commit with noreply author/committer metadata, preserving the exact reviewed tree.
- [ ] Create the annotated `v0.1.0` tag with noreply metadata. Build final assets from the clean tagged tree and record SHA-256 checksums.
- [ ] Push main and tag with an exact old-main lease; keep repository visibility private while checking a draft release.
- [ ] Re-download assets and compare checksums, release body, tag target, and repository state; publish the release.
- [ ] Delete all non-main local and remote work branches, point About to main, switch repository visibility to public, and verify public access, main/tag identity, and the absence of personal metadata in the public history.

## Review and release gates

- Never copy the developer's `.local` directory wholesale. Only the three explicitly named compiled native executables may enter the runtime package.
- Do not redistribute Codex, VS Code, authentication files, management state, receipts, raw logs, backup bundles, or local Git metadata.
- Preserve every bundled npm package's license/notice files and the full Node.js license notice for the exact selected runtime version.
- Reject package overwrite, missing artifacts, dependency version drift, reparse-point inputs, and unsafe output paths.
- Keep historical validation results and documented unknowns distinct from new packaging checks; do not claim new live-model or clean-PC acceptance.
- A public-history rewrite does not erase copies in existing clones or provider caches. Do not publish recovery refs or private backup files.
