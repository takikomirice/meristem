# Meristem v0.1.0

初回の実験的なWindows x64リリースです。VS Codeの親チャット（コーディネーター）から、独立した子チャット（ワーカー）へ工程を割り当て、報告・停止・Git統合を管理できます。ワーカーは内部サブエージェントとは別のCodex CLIチャットです。

## 主な機能

- Markdown工程表による依存関係・作業範囲の管理と、最大2ワーカーの並列実行。
- 同じ会話履歴を使う修正、新しいワーカーへの引継ぎ、質問応答と人による正式承認。
- 報告・ターン終了・後始末を確認してからのコーディネーター再開。
- Git worktree/branchの分離、候補SHAの固定、統合後の検証と次工程の解放。
- Windows Job Objectによる所有プロセスの停止確認、結果不明の指示の再送禁止、作業成果の保持。
- 日本語・英語READMEとMITライセンス。

## 導入

Windows x64、Git、VS Code 1.90以上と公式Codex拡張、.NET Framework実行環境、スクリプト実行が許可されたPowerShellが必要です。ZIP版ではNode.jsの別途導入やコンパイルは不要です。展開後のREADMEに従って確認し、専用プロファイル・正式なChatGPTログイン・そのPC向けの実行設定を準備してください。

専用環境の設定と実行許可は利用者が行います。設定済みのワンクリックインストーラーではありません。対応を実証したCodexは `0.169.0-alpha.11.1` です。

## 検証と制約

既存の専用環境で、実Codex/VS Codeによる直列・並列作業、同履歴修正と引継ぎ、質問と承認、Git統合、停止・再読込み・設定復元を確認しています。新しいReleaseのパッケージは、内容・ライセンス・ハッシュと展開先での本体読込みを検査します。この配布版での新しいPC・新しい実モデル受入は行っていません。

ワーカーへの直接入力、対話型TUI、任意の承認API、VS Code終了後の継続実行・自動復元は対象外です。過去の起動・切断失敗には原因未特定のものがあり、実験段階であることに注意してください。

## English

Initial experimental Windows x64 release. Meristem coordinates independent Codex CLI Workers from a VS Code Coordinator chat, with staged plans, up to two parallel Workers, reporting, human approval, verified Git integration, and owned-process stop controls. Workers are independent chats rather than internal subagents.

Use the Windows ZIP for the compiled runtime, helper VSIX, bundled Node.js, locked dependencies, licenses, and bilingual setup guides. The standalone VSIX contains only the helper extension. Verify downloads with `SHA256SUMS.txt`. GitHub's generated source archives do not include the built runtime or Node.js.

You still need Git, VS Code with the official Codex extension, the .NET Framework runtime, permitted PowerShell scripts, dedicated configuration, and official ChatGPT authentication. No credentials or developer state are included. This is not a one-click configured installer. Tested live Codex version: `0.169.0-alpha.11.1`.

Existing dedicated-environment acceptance is documented separately. The packaged runtime is checked for contents, licenses, hashes, and imports from the extracted bundle; no new clean-PC/live-model acceptance is claimed. Direct Worker input, TUI, arbitrary approval APIs, and execution or automatic recovery after VS Code exits are unsupported. Some earlier startup/disconnect failures remain unexplained.
